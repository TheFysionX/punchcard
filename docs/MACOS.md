# macOS support and final verification

Punchcard's macOS implementation is complete at the source, package, and CI-validation level. A real Mac is still required for the final visual and lifecycle verification because Windows cannot instantiate AppKit, inspect a live macOS GUI launchd domain, or connect to Discord's macOS Unix socket.

## Implemented behavior

- One global npm install provides the daemon and a menu-bar item. No second app bundle, Xcode installation, or developer certificate is required.
- The menu is built with the system JavaScript for Automation bridge to AppKit. It runs as an accessory application, so it has a menu-bar item but no Dock icon.
- A user LaunchAgent at `~/Library/LaunchAgents/com.punchcard.presence.plist` starts the long-running `tray-host --login` supervisor in the Aqua login session.
- The LaunchAgent has `RunAtLoad` enabled and `KeepAlive.Crashed` enabled. A crash restarts it; a clean Quit does not. Start-at-login remains configured for the next login.
- The LaunchAgent stores absolute Node and Punchcard CLI paths, is mode `0600`, and is managed with `launchctl bootstrap`, `bootout`, `enable`, and `disable` in the user's `gui/<uid>` domain.
- Menu actions use `NSTask` with the absolute Node and CLI paths and argument arrays. No shell command string is evaluated.
- The macOS menu host performs the same opt-in 15-minute automatic update check/install cycle as the Windows tray.
- Discord IPC searches the official macOS/Linux runtime roots and `discord-ipc-0` through `discord-ipc-9`.
- New macOS installations use `~/Library/Application Support/Punchcard`. Existing legacy state at `~/.claude-codex-presence` remains in place unless `PUNCHCARD_HOME` explicitly selects another directory.
- Claude hooks use the user settings file under `~/.claude` or `CLAUDE_CONFIG_DIR`. Codex sessions use `CODEX_HOME`, and sidechat discovery checks `CODEX_SQLITE_HOME`, `~/.codex/sqlite/state_5.sqlite`, and the legacy top-level database.
- Advanced Metrics can resolve Codex from the interactive PATH, Punchcard's Node prefix, the current native `~/.local/bin/codex` location, and the standard Apple-silicon or Intel Homebrew prefixes. Unknown layouts remain unavailable instead of being guessed.

## Automated gates

`npm run release:check` performs the normal unit and package checks on Windows, Linux, and macOS. On a macOS runner it additionally:

1. renders the exact LaunchAgent generated by the package and validates it with `/usr/bin/plutil -lint`;
2. compiles `scripts/tray-macos.js` with `/usr/bin/osacompile -l JavaScript`;
3. runs synthetic tests for launchctl lifecycle calls, clean-Quit semantics, paths containing spaces, App-bundle exclusions, terminal Claude/Codex processes, Codex database candidates, and npm prefix layouts.

These are static and simulated checks. They deliberately do not claim that the menu appeared on a real display.

## Final real-Mac checklist

Use a disposable macOS user account with current Discord Desktop, Node.js 22 or newer, Codex, and Claude Code installed. Test Apple silicon first; repeat the install/start smoke test on Intel if Intel is a release requirement.

```sh
npm install -g punchcard-presence
punchcard doctor --json
```

Verify all of the following:

1. A `P` item appears in the menu bar and Punchcard does not appear in the Dock.
2. The menu reports the installed version, Discord connection, active platform/agent count, and token totals.
3. Each of Presence, Start at login, Automatic updates, agent count, daily tokens, weekly tokens, More Metrics, and profile visibility changes state and remains correct after reopening the menu.
4. Connect/refresh Discord, View profile, Check for updates, Restart, and Quit execute once.
5. Quit removes the Discord activity and menu item and does not reopen it during that login session.
6. After logging out and back in, Punchcard starts again when Start at login was left enabled.
7. Turning Start at login off leaves the current menu available but prevents the next-login start; turning it back on restores it.
8. One active Codex main task, one Codex sidechat, one Claude main turn, and one Claude subagent each change only their intended count. Idle desktop shells, Codex app-server helpers, Claude remote-control listeners, and Electron helpers do not count.
9. A continuous active period keeps one Discord elapsed timer; zero active agents removes the activity and resets the next active period's timer.
10. With More Metrics enabled, the profile receives real aggregates and the Codex official-usage probe resolves when Codex is installed through the standalone installer, Homebrew, or the same npm prefix as Node.
11. No Full Disk Access prompt appears with default `~/.claude` and `~/.codex` locations. If custom roots point into Documents/Desktop/Downloads, verify Punchcard fails closed until macOS grants the relevant user permission.
12. `punchcard off` removes the LaunchAgent and Punchcard-owned Claude hooks without altering other Claude settings.

Record the `punchcard doctor --json` output, macOS version, architecture, Node version, Discord version, Codex version/install method, and Claude version/install method with the release evidence. Do not attach prompts, transcripts, session files, credentials, or the Advanced Metrics signing key.

## Source basis

The implementation follows Apple's current launchd property-list and `launchctl` contracts, AppKit status-item APIs, Foundation task/timer APIs, and standard Application Support location guidance:

- [Apple launchd.plist manual](https://keith.github.io/xcode-man-pages/launchd.plist.5.html)
- [Apple launchctl manual](https://keith.github.io/xcode-man-pages/launchctl.1.html)
- [Apple NSStatusItem](https://developer.apple.com/documentation/appkit/nsstatusitem)
- [Apple accessory activation policy](https://developer.apple.com/documentation/appkit/nsapplication/activationpolicy-swift.enum/accessory)
- [Apple NSTask](https://developer.apple.com/documentation/foundation/process)
- [Apple Timer](https://developer.apple.com/documentation/foundation/timer)
- [Apple File System Programming Guide](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/FileSystemProgrammingGuide/FileSystemOverview/FileSystemOverview.html)
- [Apple privacy controls for files and folders](https://support.apple.com/guide/mac-help/control-access-to-files-and-folders-on-mac-mchld5a35146/mac)

Product integration follows the official Discord RPC socket contract, npm global-prefix layout, Claude hooks/settings documentation, and current upstream Codex storage observations:

- [Discord RPC documentation](https://docs.discord.com/developers/topics/rpc)
- [npm folders](https://docs.npmjs.com/cli/v11/configuring-npm/folders/)
- [npm scripts](https://docs.npmjs.com/cli/v11/using-npm/scripts/)
- [Claude Code hooks](https://code.claude.com/docs/en/hooks)
- [Claude Code settings](https://code.claude.com/docs/en/settings)
- [Claude Code installation troubleshooting](https://code.claude.com/docs/en/troubleshoot-install)
- [OpenAI Codex shared state discussion](https://github.com/openai/codex/issues/20864)
- [OpenAI Codex app-managed SQLite location report](https://github.com/openai/codex/issues/29953)

Codex local storage is not a stable public API. Those upstream issue reports are compatibility evidence, not a guarantee; Punchcard therefore checks only known layouts and fails closed on unreadable or changed schemas.
